# 03-BRIEFS

## Qué va aquí

Briefs listos para convertirse en contenido o decisión. Una capa intermedia entre "tengo una idea conectada" y "tengo algo publicado/decidido".

Un brief tiene tesis, evidencia, audiencia y siguiente paso. No es publicable como está, pero ya está listo para entrar a producción.

## Cuándo agregar algo

- Una conexión de `02-CONNECTIONS/` ya está madura y vale la pena estructurar.
- Vas a escribir un post, grabar un video, o tomar una decisión formal, y necesitas el guion antes de ejecutar.
- Un cliente o colaborador te pide un documento de posición sobre un tema.

## Cuándo NO agregar acá

- **Cuando todavía es exploración.** Va a `01-CAPTURES/` o `02-CONNECTIONS/`.
- **Cuando ya está publicado o ejecutado.** Va a `04-PUBLISHED/`.
- **Cuando es planeación de un proyecto en marcha.** Va a `06-PROJECTS/<proyecto>/`.

## Ejemplo genérico

`brief-post-onboarding-quick-win.md`

```
fecha: 2026-05-12
tipo: post de blog
audiencia: founders early stage que están midiendo churn

Tesis: el onboarding no falla por flujo, falla por ausencia
de un primer "click feliz" antes del paso 4.

Evidencia:
- 3 patterns convergentes registrados en últimos 2 meses
- Caso propio: churn -18% tras introducir win en paso 2

Estructura del post:
1. Anécdota inicial (paso 4 abandono)
2. Definición de "click feliz"
3. Cómo identificar el tuyo
4. Cierre con caso propio

CTA: descargar mini-checklist
```

## Convención

Cada brief tiene: tesis, evidencia (con rutas a capturas), audiencia, estructura, CTA. Sin esos cinco campos no es brief, es draft.
